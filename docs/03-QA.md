## QA summary

- **Critical failures (4):** QA-LOG-01/05 (login session, FN-01), QA-AUZ-01 (route guard, FN-02), QA-DSH-01 (count mismatch, UX-01).
- **The SOC console passed every case** (8/8) — it is production-grade and the model the rest of the app should follow.
- **DB-dependent cases are blocked**, not passed — the success path of registration and login could not be exercised end to end. Re-run QA-REG-01, QA-LOG-02 once `DATABASE_URL` is configured.
- **The pattern across failures:** UI asserts an outcome (logged in, suspended, MFA enforced, report generated) that the system did not perform. This is the single most important theme to fix — a security product that lies about state is worse than one that errors.
